# @deepseek-ai/dsh-vision-bridge

简体中文 | [English](README.md)

自动视觉桥接：把文本模型路由上的 agent-loop 请求中的图片内容，转换为配置的视觉观察器产出的文本证据，让粘贴图片在无法看图的模型上继续可用。

## 工作原理

对每个满足以下条件的 `llm/stream` 请求——是 agent-loop 请求、携带图片块、且目标模型未声明 `image` 输入：

1. 每条携带图片的用户消息的图片按 `ctx.vision.maxImagesPerRequest` 分批，每批以消息文本作为问题观察（命中缓存则复用）。
2. 每次观察追加一条 `ignorable` 的 `vision/observed` 会话事件（消息 id、附件、证据、视觉路由、用量），转换后的请求可从会话日志重建。
3. 请求被转换——每个图片块替换为该批的证据块——并通过同一 LLM 能力缝派发。

`user/message` 事件保持原样：UI 画廊继续渲染原始图片；"模型可见 ⟺ 可记录"不变量成立，因为循环自身的请求不变（不变量把它与日志比对），而被替换的证据记录在追加的事件中。

模型可见的证据块固定如下信封：

```
<vision-evidence message-id="..." attachment-ids="...">
<content>
...evidence text...
</content>
```

非 agent-loop 请求（手工构建的调用、桥接自身的视觉调用）原样通过，因此无需重入防护。视觉能力路由原生透传——`read_image` 继续可用——因为桥接只在确切路由模型缺少图片输入时转换。

## Model Experience

### 转换后请求上下文

#### 模型所见

在文本路由上，携带图片的请求到达 adapter 时，每个图片批次已被其证据块替换；其余消息不变。证据文本是视觉模型的输出（见 `dsh-vision-llm`），不是固定字符串。

#### Token 效果

每次转换请求：每个未缓存图片批次一次观察请求（输入 = 提示词 + 问题，输出 = 证据），主请求本身不变。已缓存批次（同消息同附件，记录在日志中）零成本。

#### KV Cache 效果

主请求前缀经转换不变，Provider 侧前缀缓存行为与无桥接时一致。

## Known Limitations and Deferred Work

- **仅文本路由**——声明 `image` 输入的模型原生接收图片；桥接从不为其转换。
- **观察失败即请求失败**——观察失败以该路由的 `LlmError` 呈现并流入循环既有的重试机制；请求绝不会静默降级为纯文本猜测。
- **压缩可能丢弃证据事件**——若压缩删除 `vision/observed` 事件，后续请求重新观察受影响图片（幂等，但花费一次视觉调用）。
- **重复请求只补观察缺失**——证据按消息 + 附件从会话日志缓存；修改观察提示词在进程重启前不会使缓存失效（日志保持权威）。
