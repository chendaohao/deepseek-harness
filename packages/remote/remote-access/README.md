# @deepseek-ai/dsh-remote-access

English | [中文](README.zh.md)

Remote-access consumer of the remote-tunnel capability: the pairing gate, the loopback reverse proxy, and the URL + QR surface. The shipped Web row enables it from `dsh web --remote`; config `{enabled, resetSecret, wsCompression}`. On init it loads or creates the 32-byte pairing secret (`$DSH_HOME/secrets/remote-pair`, 0600 under a 0700 directory; `resetSecret` rotates it first), starts a loopback-only proxy on an OS-assigned port, opens a tunnel to that port after Loader settlement, prints `dsh web remote: https://<slug>.trycloudflare.com/pair/<ticket>` plus a terminal QR code, and registers `DSH_REMOTE_URL` through the shell-env seam — present only while a session lives.

Security model: the proxy is the only public trust boundary. `GET /pair/<ticket>[?name=<device name>]` verifies the day-scoped HMAC ticket in constant time and answers 302 with a `v2.<deviceId>.<mac>` `HttpOnly; Secure; SameSite=Strict; Path=/` cookie whose 30-day Max-Age refreshes with use; each pairing binds one device in the registry (`$DSH_HOME/secrets/remote-devices.json`, atomic 0600 writes) labeled by the `?name=` parameter (kept to 64 characters) or the User-Agent prefix. Every other request and upgrade must present a cookie whose device binding is inside its sliding window: admission refreshes `lastUsedAt`, and 30 consecutive idle days unbind the device automatically (its next request answers 401 with the pairing-hint page) — there is no Host- or address-based shortcut, because behind the tunnel every connection arrives from the loopback address and the Host header is client-controlled. On the first admitted request of each UTC day the relayed response echoes a fresh Set-Cookie so a continuously-used browser cookie never ages out. Failed pairing attempts count toward a failure budget (10 per 10 minutes) keyed by client address; behind the tunnel every remote client shares the loopback address, so the budget is global, and a correct ticket always succeeds and clears the window. Forwarded requests get their Host rewritten to the webserver bind authority (loopback under the shipped defaults) and browser-trust headers removed, so the existing `/api` trust fence applies unchanged; the privileged settings/credentials/agent-preset endpoints are therefore reachable with a valid cookie — the Web UI keeps them in a per-session memory scope on non-loopback pages, and native host dialogs stay local. WebSocket upgrades pass the same gate (authorized once at upgrade; the window slides on the next plain request); downstream frames arriving before the upstream handshake completes are buffered within a byte bound, and per-frame and send-queue bounds refuse flooding pairs. Relayed WebSocket frames are compressed with permessage-deflate on the public tunnel leg when `wsCompression` is on (the default; the loopback leg stays plaintext, where compression would buy nothing) — clients that do not offer the extension transparently negotiate none, so legacy clients are unaffected. A tunnel exit reopens the tunnel with linear backoff (5 attempts, reset on success) and reprints the URL/QR under the new hostname; bindings survive a hostname change, and `resetSecret` rotates the secret and clears every binding. The transport under the tunnel carries the connection package heartbeat/watchdog pair: the host heartbeats both WebSocket downlinks while idle, and the phone-side client recycles its generation when frames stop (default detection ≈45 s) or immediately on the browser network-change signals — a phone switching mobile data ↔ WiFi tears its sockets without a close frame, and this is the exact failure mode those two mechanisms cover.

The `remoteAccessDevices` Remote service (typert namespace, registered only while the plugin is enabled) exposes the registry to the Web GUI: `list()` returns the live bindings with their `expiresAt` deadline, and `unbind(deviceId)` removes one — the Web Settings Remote Access page ([ui-settings-remote](../../client/ui-settings-remote/README.md)) renders that list and the manual unbind.

## Model Experience

Indirectly, through the `DSH_REMOTE_URL` shell-env contribution this package registers; the shell tools own what reaches a model request.

#### KV Cache effect

None; the contribution adds one per-shell environment value and does not touch request assembly.

## Known Limitations and Deferred Work

- **UI-scoped privileged plane** — the Web UI keeps settings, credentials, and agent-preset authoring in a per-session memory scope on non-loopback pages, and native host dialogs stay local; the endpoints themselves sit behind pairing auth. Host-plane exposure behind pairing auth waits for the auth layer to earn real-world mileage.
- **In-GUI remote status is the device list only** — the URL/QR surface is the terminal; a GUI badge for tunnel state needs a forwarded event and is deferred until a consumer exists.
- **Day-scoped tickets** — the QR re-pairs any device for the current UTC day; after the day rolls or after `--remote-reset`, scan a fresh QR. Cookies outlive both until expiry.
