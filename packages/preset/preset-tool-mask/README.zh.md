# @deepseek-ai/dsh-preset-tool-mask

[English](README.md) | 中文

## Summary

预设可以添加插件行、可以用同名行遮蔽宿主行，但预设里没有任何东西能移除一个全局工具。一个只声明 `read` 与 `write` 的审核员预设，依旧带着部署的 shell、MCP 文件编辑工具、任务板和其余全部宿主工具，只能靠人设文字请模型不要用它们。这个包补上这个缺口：把它挂在预设第一行，该预设作用域看到的全局目录就被收窄到声明保留的名字，由该预设组合出的每个 Agent 沿作用域链继承这项收窄。宿主自己的 Agent 仍持有完整目录。

<a id="use-this-package"></a>
## 使用本包

把它挂在「角色不该持有部署全部工具目录」的预设的第一行。这一行属于预设，不属于 profile：同一个 profile 同时服务一个全权 Agent 和三个收窄角色。

### 何时选择它

当预设人设要求模型不要用某个能力、而部署仍然把该能力交给它时，选它。掩码让收窄变成事实而非劝告，同时缩小模型每次请求都要付费的工具 schema。不要选它的情况：预设确实需要宿主目录；部署会在预设加载后挂载名字无法用前缀预测的工具。

### 声明掩码

```yaml
- id: preset-tool-mask
  name: '@deepseek-ai/dsh-preset-tool-mask'
  config:
    allow: [read, write, bash, todo_write]
    allowPrefixes: ['mcp__codegraph__']
    deny: [task_board_run]
```

| 字段 | 默认 | 含义 |
|---|---|---|
| `allow` | `[]` | 精确保留的全局工具名 |
| `allowPrefixes` | `[]` | 按前缀保留，用于成员随部署变化的族 |
| `deny` | `[]` | 在保留列表之后精确剔除的名字，用于从保留的族里切掉一个 |
| `denyPrefixes` | `[]` | 在保留列表之后按前缀剔除 |

凡是没被 `allow` 或 `allowPrefixes` 保留的全局工具都会被隐藏。预设自己的行不受影响：预设自行注册的工具即使没有任何 allow 条目点名，也仍然可见。

### 得到什么

该预设里的模型只收到被保留的 schema，它每次请求读到的工具目录与人设要求它做的事一致。`allow` 里部署未注册的名字会警告一次并忽略，因此同一个随包预设在有可选插件缺失的部署里照样能挂载。

<a id="understand-the-implementation"></a>
## 理解实现

### 设计取舍

掩码是推导出来的，不是枚举出来的。把 `allow` 与 `allowPrefixes` 展开到当前全局目录，意味着部署多挂一个插件也会顺带被收窄，无需改预设；反过来，让预设逐个列出要丢的工具，会在下一个插件加载时立刻过期。`tools/change` 会重新展开，因此预设挂载之后才到达的工具同样被隐藏，不会漏进来。

限制施加在预设作用域上，而不是上下文全局表上。该预设组合出的 Agent 以这个作用域为父，工具注册表沿作用域链求交，因此收窄一个预设不会动到其他 Agent 的目录。

### 源码导览

| 模块 | 职责 |
|---|---|
| `src/index.ts` | `Config` 校验、推导 deny 列表、`tools/change` 刷新 |

<a id="model-experience"></a>
## 模型体验

### 收窄后的工具目录

#### 模型看到什么

只看到被保留的 schema。一个从上百个工具里保留四个的预设，其目录体积只剩零头，而这笔开销在会话的每次请求都要付一次。被掩码隐藏的工具完全不在目录里：模型读不到它的名字、描述与参数 schema，凭记忆发起的调用以 `UNKNOWN_TOOL` 结算。

#### Token 影响

随目录收缩而下降：被移除的 schema 不再重发。掩码本身不增加消息、不增加提示词段落、不增加工具。

#### KV Cache 影响

只要保留集合不变，目录前缀就是稳定的。改变保留集合的 `tools/change` 会从第一处差异起重发目录，与一次工具注册的行为相同。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

这些限制说明掩码在什么情况下不合适。它们是当前包约束，不是任务清单。

- **隐藏不等于禁止** —— 掩码只是把 schema 从模型目录里移除，不拒绝凭过期目录发起的调用。这类调用会到达执行器并以未知工具结算，预设看到的就是一次普通工具失败。
- **前缀覆盖名字，不覆盖意图** —— 部署在预设挂载之后注册、且名字不匹配任何已声明前缀的工具，预设无法保留；刷新会像对待其他未保留工具一样把它隐藏。
- **声明绑定于预设修订** —— 改动它会重挂预设，因此上一修订下已在运行的 Agent 在新修订生效前仍持有旧掩码。
- **掩码不能凭空造出工具** —— 预设保留的是宿主注册过的工具。宿主从未挂载的工具无法被点名引入，为它写 `allow` 条目只会得到一次警告。

包目录刻意不叫 `tool-*`：工具目录生成器会把每个 `packages/*/tool-*` 包当作随包工具启动，并拒绝一个不注册任何工具的包。

另一种设计 —— 在委派行上声明 `toolFilter` —— 已于 2026-10-09 移除，因为该过滤属于子代理的组合，而不属于父代理的调用。掩码保留那个决定，并把收窄挪到组合本身所在的位置。
