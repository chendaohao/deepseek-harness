# Agent Note: 会话统计条在手机上点击展开

Status: implemented

[English](2026-09-06-stats-line-tap-reveal.md) | 中文

## 问题

在手机上，输入框下方的会话统计条（"1 轮 · 2 步 | LLM … | …"）在视口底部截断为一行，溢出的内容——耗时、token 速率、缓存命中、计费——无法查看：该条唯一的展开手段是共享的悬停 Tooltip，其触摸路径（点击 → 气泡 → 3 秒自动消失，来自 2026-08-18 的触摸卫生提交）在真实手机上不触发。在带插桩的移动 Chromium 会话里，点击的 `pointerdown` 到达了该条的 DOM 元素，React 也持有克隆的 `onPointerDown` prop，但 React 的委托派发从未执行它（直接调用 prop 能弹出气泡；可信触摸事件和冒泡的合成 `PointerEvent` 都无效，而 `click` 委托正常——同一次点击能让 + 按钮的指令菜单打开）。无论引擎层的根因是什么，该条都不能依赖它。

## 决定

**该条用自己的 `click` 驱动的点击阅读展开。** `StatsLineContent` 把统计条包进一个定位包装元素；当该行量得截断时，点击会把完整统计展开为统计条上方锚定的 Tooltip 样式面板（用 `click` 而非 `pointerdown`，让手势走每台触摸浏览器都会派发的兼容事件路径），保持 3 秒后收起；再次点击立即收起；展开期间的点击会重新武装阅读计时。共享的悬停 Tooltip 保留给指针用户，面板展开期间禁用。面板复用 Tooltip 的表面配色对（`--dsh-alias-tooltip-bg` / `--dsw-static-neutral-bluish-00`），使两者读起来是同一类交互；面板横跨共享内容宽度轴（从 `.root` 上移到包装元素），换行而不是裁切。

## 备选方案

**改为修 Tooltip 的触摸路径。** 暂缓：该失败闯过了测试装置里所有派发层的探查（原生监听触发、传播完整、容器上注册了委托 `pointerdown` 监听、无任何报错），此时修复只能对仓库可观察范围之外的机制下注。该条自己的展开不需要它；一旦引擎层根因被定位，Tooltip 的修复对 composer 工具栏其余的点击气泡仍然值得做。

**用 Modal 或浮层展示完整统计。** 否决——这只是临时的一眼阅读支持，不是一个界面：不应夺取焦点、挡住输入框，也不应带来额外的清理义务。

## 后果

在手机上，点击截断的统计条会展示完整数字 3 秒后收起；桌面端视觉不变（悬停保留原气泡；点击现在也能作为点按阅读）。未截断的场景 golden 不受影响：包装元素只在量得截断时才添加交互光标和点击处理。

## 验证

一次 keyless 回放的手机运行（360×740、触摸、中文）驱动了完整的 ask_user_question 往返：点击 → 面板带着完整统计挂载，3 秒阅读期后自动收起，第二次点击重新展开，第三次立即收起。`npx vitest run packages/client/ui-chat`（317 通过）， touched 文件的 oxlint/tsc 保持绿色。

同一次验证发现的后续修复：尺寸属性上移后 `.root` 丢了 `box-sizing: border-box`，两侧 padding 变成在包裹层之外再加 64px——手机列宽下统计条盒子越出聊天滚动视口，其计算出的 `overflow-x: auto` 就地在右侧滚动条旁边显示了横向滚动条。`.root` 重新带上 `box-sizing: border-box`；360×740 的回放探测确认统计条渲染后滚动容器 `scrollWidth` 回到 `clientWidth`（296）。
