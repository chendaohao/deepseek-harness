# Agent Note: 自动置顶跟随会话活跃，空闲一小时后过期

Status: implemented

[English](2026-10-13-automatic-session-pin.md) | 中文

## Problem

只有手动置顶时，正在干活的会话无法自动待在顶部：开工前先置顶、完工后记得取消，恰恰是置顶区要消灭的那类记账动作。需求是：会话活跃时自动置顶，活动结束满一小时后移除该置顶——同时绝不让自动化碰用户亲手放置的置顶。

## Decision

Workspace 注册表把自动置顶作为其持久全局状态里的第二类条目。`autoPinnedSessions` 记录每个自动置顶及其最近一次活动的 ISO 时间戳；既有的 `pinnedSessionIds` 数组仍是手动与自动置顶共用的唯一显示顺序。该字段带 zod 默认值，因此领域版本保持 2，字段加入之前写入的记录原样解析（沿用 `pinnedSessionIds` 的先例）。

活动信号是推送而非轮询。Agent 注册表的 `installActivityAutoPin` 把每一次 `agent/status` 变迁以可见会话记录给 `noteSessionActivity(sessionId, phase)`——子代理的活动解析到它最近的非子代理祖先，与归档准入对「会话仍有工作」的口径一致。`active` 记录为未置顶、未归档、未抑制的会话自动置顶；两个相位都会重置空闲时钟。

过期靠扫掠而非逐会话定时器。分钟级的 `sweepAutoPins()` 为每个自动置顶询问 `workspace/session-activity` waterfall：提供方仍报告工作就刷新时间戳（跑三小时的回合保住自己的置顶），时间戳满一个 `autoPinIdleTimeout`（默认一小时）就移除置顶。启动时的一次扫掠清掉上一轮运行留下的过期置顶。两个旋钮都是插件的可选 `Config` 字段；扫掠失败记日志并在下一拍重试。

手动置顶是硬边界。显式 `pinSession` 通过删除条目把自动置顶升级为手动置顶，扫掠永不管理用户认领的置顶。手动取消一个自动置顶会记录一条内存中的抑制，使活动源在同一活跃期内不再加回；`idle` 记录解除抑制。抑制刻意不持久化——宿主重启本就会结束它所覆盖的活跃期。

## Alternatives considered

**在客户端投影活跃会话而不是在宿主上置顶。** 置顶集合保持纯手动，每个分组界面各自从状态快照推导「活跃」。这把规则放进了每个消费方而不是唯一持有置顶顺序的注册表，两台设备会看到不同的置顶。

**靠轮询发现活跃会话。** 按周期对每个已知会话询问活动 waterfall 可以不新增监听器就发现工作，代价是每拍每个会话一次 waterfall，且开工时没有即时置顶。推送式活动源在变迁发生时就置顶；扫掠只需复核很小的自动置顶集合。

**逐会话空闲定时器。** 每个自动置顶一个定时器能精确对齐超时，但句柄成倍增加，且重启持久性要另讲一套；单周期扫掠从持久化的时间戳推出一切。

**持久化抑制。** 把「用户移除了这个自动置顶」持久化能扛住重启，但它活得比它记录的条件更久：用户反对的是某一段工作期间的重新置顶，而不是永远。空闲变迁是天然的活跃期边界，而重启本就会结束任何进行中的活跃期。

## Consequences

自动置顶在线缆上和客户端里与手动置顶无从区分：`pinnedSessionIds` 经由既有的 follow feed 流出，因此每个界面——工作区分组上方的侧栏置顶区、单列表——无需客户端改动就能显示自动化放置的置顶。

回合族是触发源，但每个族都能续期：任务、子代理与定时提醒通过扫掠让自动置顶在没有回合运行时保持有效，与归档准入的口径一致。未组合 Agent 注册表的部署保持纯手动置顶。

## Testing

`packages/workspace/workspace/tests/workspace.spec.ts`（`registry-global automatic session pin`）：活动源行为（置顶、重置时间戳、空闲重启时钟）、守卫（已归档、手动置顶、被抑制）、升级、归档移除自动条目、扫掠（过期移除、活跃刷新、安静时不写、遗留条目不经询问即丢弃、启动失败记日志且写链完好）与重启持久性。`packages/core/agent/tests/auto-pin.spec.ts` 覆盖活动源：普通与祖先解析的变迁、断裂的血缘、缺失的注册表、被容错的记录失败。
